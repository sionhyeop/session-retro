# session-retro v1.1 설계서 — "중간 도입" (에피소드 체계)

- 날짜: 2026-07-28
- 상태: 사용자 승인됨 (구현 전)
- 기반: `2026-07-28-session-retro-design.md` (v1). 이 문서는 v1의 §5.2/§6/§7을 확장·변경한다.

## 1. 목표

이미 진행 중인 프로젝트에 스킬을 중간 도입해도 "알아서 잘 정리"되게 한다.
① 쌓인 과거 세션을 주제(기능/문제) 단위 **에피소드**로 분할해 블로그 여러 편 + 지식전달용 개요로 정리하고,
② Claude가 먼저 회고를 제안하게 만들어 사용자가 스킬의 존재를 의식하지 않아도 되게 한다.

## 2. 확정된 결정

| # | 결정 | 선택 |
|---|---|---|
| 1 | 에피소드 분할 기준 | **순수 기능/문제 단위**(git 스코프 + 세션 제목). 한 에피소드가 과대해지면(여정 문제 4개 초과 또는 블로그 1편 분량 초과) **1부/2부 분할 제안**(승인제), 부작이 되면 velog 시리즈명 제안(시리즈 API 연동은 v2) |
| 2 | overview.md 형식 | **온보딩 문서형** — 새 합류자·미래의 내가 30분 안에 따라잡는 문서 |
| 3 | 증분 세션 귀속 | Claude가 기존 에피소드 병합 vs 신규를 제안하고 사용자 확인 |
| 4 | 넛지 | SessionStart 훅으로 컨텍스트 주입(AI 호출 없음). 활성 프로젝트=체크포인트 제안, 미활성+세션 3개 이상=소급 모드 안내. compact 재시작에는 넛지 안 함 |

## 3. 구조 변경 (v1 §5.2 대체)

```
<프로젝트>/retro/
├── archive/                       # (v1과 동일)
├── assets/auto/ · assets/inbox/   # (v1과 동일)
├── specs/YYYY-MM-DD-<slug>.md     # 에피소드별 회고 스펙 (블로그 1편 = 1개; 부작은 -part1, -part2)
├── overview.md                    # 온보딩 문서형 개요 (에피소드 목차 포함)
└── out/blog/ · out/ppt/           # (v1과 동일)
```

- 스펙 파일명 날짜 = 에피소드 시작일. 내용 형식은 v1 §6과 동일(frontmatter + 여정 등).
- **마이그레이션**: 구버전 단일 `retro/spec.md` 발견 시 `retro/specs/<updated날짜>-<slug>.md`로 이동을 제안.

## 4. overview.md 계약 (온보딩 문서형)

```markdown
---
title: <프로젝트명> 개요
updated: YYYY-MM-DD
---
## 한 줄 소개
## 왜 만들었나            # 배경·목표·제약
## 아키텍처 큰 그림        # 텍스트 다이어그램/mermaid 허용
## 중대한 결정들           # "왜 A 대신 B" 표: 결정 / 선택 / 이유
## 지뢰밭 지도             # 우리가 밟은 삽질 → 다음 사람은 밟지 않도록: 증상 / 원인 / 회피법
## 에피소드 목차           # specs/의 각 에피소드: 제목·기간·한 줄 요약·상태(스펙만/블로그 발행/덱 있음)
```

`/retro`가 에피소드를 만들거나 갱신할 때마다 목차와 관련 섹션을 함께 갱신한다.

## 5. retro 스킬 동작 (v1 §7.2 확장)

**모드 판정** (스킬 실행 시): `retro/specs/`가 비어 있고 프로젝트에 세션 기록(현재 보관분+archive)이 3개 이상이면 **소급 모드**를 제안, 아니면 **증분 모드**.

**소급 모드**:
1. `scripts/inventory.py` 실행(AI 호출 없음) → 세션(제목·기간·턴·도구실패) × git 커밋 교차표 + "세션 기록이 없는 커밋" 목록(30일 경과 소실분·Claude 밖 작업) 생성.
2. Claude가 표를 읽고 기능/문제 단위 에피소드 클러스터를 근거(세션·커밋)와 함께 제안 → 사용자 큐레이션(병합/분리/제외/우선순위).
3. 승인된 에피소드부터 **한 번에 1~2개씩** 스펙 생성(컨텍스트 관리) — 각 에피소드의 세션들을 parse_transcript로 파싱해 증류. 세션이 소실된 구간은 git 뼈대를 서술하고 **사용자 인터뷰("이때 뭐가 힘들었어요?")로 디테일 보완**.
4. overview.md 생성/갱신.

**증분 모드**: 현재 세션 파싱 → 내용 기준으로 "기존 에피소드 X에 병합 vs 새 에피소드" 제안 → 승인 후 해당 스펙 갱신 + overview 목차 갱신.

**분량 가드레일**: 스펙의 여정 문제가 4개를 초과하거나 예상 글 분량이 명백히 1편 초과이면 부작 분할을 제안한다.

## 6. 출력 스킬 변경

- **retro-blog**: `retro/specs/*.md`가 여러 개면 목록을 보여주고 선택받는다(기본: 최근 갱신). 구 `retro/spec.md`도 폴백 지원. 부작 스펙은 부별로 글 생성 + 시리즈명 제안.
- **retro-ppt**: 발표 대상 선택 — ① 에피소드 1개(해당 스펙) ② 프로젝트 전체(overview.md 기반: 개요→에피소드 하이라이트→지뢰밭→다음).

## 7. 넛지 훅 — `hooks/retro_nudge.py` (SessionStart)

- stdin: v1과 동일 공통 필드 + `source`. `source == "compact"`이면 침묵.
- `retro/` 있음: 스펙류(specs/*.md, spec.md, overview.md) 최신 mtime보다 새로운 archive 파일이 1개 이상이면 → additionalContext로 "재료 N개 쌓임, 사용자가 마무리·정리를 원할 때 /retro 체크포인트를 한 문장으로 제안(먼저 꺼내지는 말 것)" 주입.
- `retro/` 없음: `~/.claude/projects/<munged-cwd>/`의 세션이 3개 이상이면 → "사용자가 회고·블로그·발표를 언급하면 소급 모드 안내" 주입.
- 그 외에는 출력 없음. 어떤 실패에도 exit 0. hooks.json과 install.sh에 SessionStart 등록 추가(멱등).

## 8. inventory.py 계약

- CLI: `inventory.py [--sessions <jsonl...>] [--repo DIR] [--out FILE]` — 기본은 cwd munging으로 세션 자동 탐색(현재 보관분 + retro/archive, 세션ID로 중복 제거·원본 우선).
- parse_transcript의 `parse_lines`를 재사용해 세션별 제목/기간/턴/도구실패 추출.
- git: `git log --format=%h%x09%aI%x09%s` → 커밋을 세션 시간창(±30분)에 귀속, 미귀속은 별도 표. git 저장소가 아니면 커밋 열 없이 동작.
- 출력: 마크다운 표. AI 호출 없음, 표준 라이브러리만.

## 9. 테스트

- inventory: pytest — 세션 2개+임시 git 저장소(GIT_COMMITTER_DATE로 날짜 고정)로 커밋 귀속/미귀속, git 없음 케이스, --out.
- nudge: bash — 재료 쌓임→체크포인트 문구, 미활성+세션 3개→소급 문구, 해당 없음→출력 없음, compact→침묵, 쓰레기 입력→exit 0.
- install: SessionStart 등록·멱등 검증 추가. 기존 49개 테스트는 그대로 유지.
