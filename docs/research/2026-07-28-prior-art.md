# Part 2. 기술 파이프라인 리서치 (hooks/transcripts, velog API, HTML→PPTX)

## Q1. Claude Code hooks & transcripts

### Hook events (official: https://code.claude.com/docs/en/hooks)

~30 lifecycle events documented. Relevant, in lifecycle order: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse` (+ `PostToolUseFailure`, `PostToolBatch`), `SubagentStart`/`SubagentStop`, `Stop` (+ `StopFailure`), `PreCompact`/`PostCompact`, `Notification`, `SessionEnd`. Newer/minor: `Setup`, `UserPromptExpansion`, `PermissionRequest`, `PermissionDenied`, `TaskCreated`/`TaskCompleted`, `TeammateIdle`, `MessageDisplay`, `CwdChanged`, `FileChanged`, `WorktreeCreate`/`WorktreeRemove`, `InstructionsLoaded`, `ConfigChange`, `Elicitation`/`ElicitationResult`.

**Common stdin JSON — ALL events:** `session_id`, `transcript_path`, `cwd`, `hook_event_name` (+ when applicable `prompt_id`, `permission_mode`, `agent_id`, `agent_type`, `effort`).

**Event-specific extras:**
- `SessionStart`: `source` (`"startup"|"resume"|"clear"|"compact"|"fork"`), `model`, optional `session_title`
- `SessionEnd`: `reason` (`"clear"|"resume"|"logout"|"prompt_input_exit"|"bypass_permissions_disabled"|"other"`)
- `Stop`: `last_assistant_message` (full text), `permission_mode`, `effort`
- `PreCompact` / `PostCompact`: `trigger` (`"manual"|"auto"`)
- `SubagentStop`: `agent_type`, `agent_id`, `last_assistant_message`
- `PostToolUse`: `tool_name`, `tool_input`, `tool_use_id`

For a retro skill: `SessionEnd` is the natural archive point, `PreCompact` the "snapshot before context is destroyed" point.

### Transcript storage & retention

- Location (docs + verified locally): `~/.claude/projects/<munged-cwd>/<session-id>.jsonl` (non-alphanumerics → `-`). Sibling `.../<session-id>/tool-results/` holds oversized tool outputs. `~/.claude/history.jsonl` = global prompt history. (https://code.claude.com/docs/en/claude-directory)
- Retention: `cleanupPeriodDays`, default **30 days** (min 1); cleanup at startup. Extend: `{"cleanupPeriodDays": 90}`. `CLAUDE_CODE_SKIP_PROMPT_HISTORY` disables transcript writes. (https://code.claude.com/docs/en/settings)

### Native summarize/export features

- **`/export`** — plain text export of current conversation (clipboard or file; extensions rewritten to `.txt`). Not markdown-structured.
- **`/insights`** — report analyzing sessions (project areas, interaction patterns, friction points); interactive HTML report; ~30-day window (secondary-source only). Workflow-analysis, NOT per-session retrospective/blog — doesn't obsolete this project.
- `/rewind` "Summarize up to here" / `/resume` stale-session summarize — context management only.
- Auto-memory (`/memory`) — memory, not export.
- "Away summary" — UNVERIFIED in official docs.

### JSONL transcript schema (undocumented; verified empirically on 2.1.x)

One JSON object per line, append-only, `parentUuid`-linked tree.
- Record `type` values seen: `user`, `assistant`, `attachment`, `file-history-snapshot`, plus metadata lines `last-prompt`, `mode`, `permission-mode`, `ai-title`.
- Common keys: `parentUuid`, `isSidechain`, `type`, `uuid`, `timestamp`, `sessionId`, `cwd`, `version`, `gitBranch`, `userType`, `entrypoint`, `message` (API-shaped: content blocks `text`/`tool_use`/`thinking`; `usage`), `requestId`, `effort`; tool results = `user` lines with `toolUseResult` + `sourceToolAssistantUUID`.
- `isSidechain` on every record; subagent conversations recorded as sidechain chains. Older writeups describe `type:"summary"` lines; current files use `ai-title`/`last-prompt` — **schema is unversioned and shifts between releases; parse defensively.** (refs: https://huytieu.com/blog/anatomy-of-a-claude-code-conversation-transcript/, https://claude-dev.tools/docs/jsonl-format)

## Q2. velog publishing automation (2026-07)

- **No official public API — confirmed.** velog is open source (https://github.com/velog-io/velog) but publishes no API docs. `velog-mcp-claude`: "Velog의 공개 API가 없어 내부 GraphQL API를 리버스 엔지니어링하여 구현".
- **Endpoints (from working tool source, stoneHee99/velog-mcp `src/velog-client.ts`):** v2 `https://v2.velog.io/graphql` (reads), v3 `https://v3.velog.io/graphql` (writes). **`WritePost` mutation works** — input: `title, body, tags, is_markdown, is_temp, is_private, url_slug, thumbnail, series_id, token`.
- **Auth:** `access_token` (~1h TTL) + `refresh_token` (~30d) cookies for `.velog.io`, sent as `Cookie` header. Tools decrypt Chrome cookie DB or have user paste; backend rotates via `Set-Cookie`. Prefer user-pasted tokens stored locally.
- **Image upload — REST, not GraphQL:** `POST https://v3.velog.io/api/files/v3/upload`, multipart FormData (`image` = blob, `type` = `"post"`), cookie auth → response `path` = CDN URL (velog.velcdn.com). No presigned-URL step. (source: seongwon030/velog_mcp `src/tools/upload.ts`)
- **Risks:** v2→v3 migration precedent — endpoints may change without notice. ToS prohibits obstruction/hacking; APIs/bots not explicitly named; low-volume publishing of own posts ≈ same traffic as web editor; no documented suspension cases (UNVERIFIED). Cookie decryption tools are the scary part — prefer pasted tokens.
- **Fallback UX — good:** velog editor is native Markdown (CodeMirror); pasting full Markdown works as-is; drag-and-drop image upload confirmed (auto-inserts `![](...)`). Ctrl+V paste upload: assumed, UNVERIFIED. Size attrs need `<img width=...>`.

## Q3. HTML slides → PPTX

- **marp-cli:** `--pptx` = pre-rendered background images (not editable; presenter notes included; needs Chrome). `--pptx-editable` (v4.1.0+) = experimental, needs browser + LibreOffice Impress, lower reproducibility, no presenter notes, team does "not recommend" when appearance matters. Bonus path, not dependable.
- **Slidev:** `slidev export --format pptx` — slides exported as images, text not editable, needs Playwright Chromium.
- **reveal.js:** no native pptx; print-to-PDF or DeckTape; community converters drop fragments. Not a serious pptx path.
- **anthropics/skills `pptx`:** html2pptx pipeline is GONE (replaced in PR #330). Current: Claude writes a Node script against **PptxGenJS** directly (preinstalled), QA via `scripts/office/validate.py`, LibreOffice `soffice --convert-to pdf`, `pdftoppm` thumbnails; template editing via raw OOXML + python helpers. Deps: pptxgenjs, markitdown[pptx], Pillow, defusedxml, lxml, LibreOffice, Poppler. **License: source-available, not open source — mirror the technique, don't vendor files.** Input is a content outline, not HTML.
- **Self-contained single-file HTML decks:** hand-rolled is the established norm (nghiahsgs/skills-slides, Kuneosu/make-slide, elbruno/md-to-slides, zarazhangrui/frontend-slides, bluedusk/html-slides; 30+ catalogued at https://tosea.ai/blog/best-html-slide-skills-library-2026). Recommended: ~200-line template — absolute-positioned 16:9 stage, arrow/space/Home/End + click nav, hash-based slide URLs, `@media print` one-slide-per-page, images as data URIs.

## Recommended pipeline (Agent B)

**(1) Capture:** `/retro` skill reads live session transcript (`~/.claude/projects/<munged-cwd>/<session-id>.jsonl`; path derivable or handed by SessionEnd/PreCompact hook archiving to project `retro/` dir — archiving matters because of 30-day cleanup; suggest raising to 90). Parse defensively: keep `type: user|assistant`, walk `parentUuid` chains, skip `isSidechain: true`, extract text + tool names.
**(2) Distill:** structured retro spec (YAML/MD: goal, timeline, decisions, failures, metrics, screenshots list) — single spec drives both outputs.
**(3) Blog:** spec → velog Markdown; publish via two vendored HTTP calls (image upload REST + WritePost mutation) with user-supplied cookies; always `is_temp: true` (draft) first, print preview URL; on 4xx fall back to editor paste.
**(4) Deck:** spec → hand-rolled single-file HTML (inline CSS/JS, data-URI images, keyboard nav, print CSS); for editable pptx, generate PptxGenJS script from same spec (mirroring official pptx skill architecture). Spec-first, two renderers — no fragile HTML→pptx conversion in the critical path.
